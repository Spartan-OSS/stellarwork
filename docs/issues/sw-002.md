# SW-002: Prove role authorization with explicit Soroban auth trees

Status: **Blocked**  
Proposed Drips complexity: **High** (organizer/maintainer review required)  
Dependencies: SW-001  
Starting paths: `contracts/escrow/src/test.rs`

## Problem

Existing native happy-path fixtures mock all authorization; that cannot prove required signatures.

## In scope

- Add tests without mock_all_auths for every protected method; authorize only intended account invocation trees.
- Test creation with each of client/worker/arbitrator signatures missing.
- Assert fund requires client and nested token-transfer auth; submit requires worker; approve/refund require client; resolve requires the fixed arbitrator.
- Test outsider and spoofed actor disputes plus parameters changed after authorization.

## Acceptance criteria

- Each missing/wrong signature fails and balances/business records remain unchanged.
- Explicitly authorized positive cases pass, including nested SAC transfer.
- No authorization-negative test relies on mock_all_auths; include table mapping methods to tests.

## Excluded work

No policy/API changes, custom account contracts, wallet UI, or token allowlist.

## Verification

cargo test --workspace --locked
