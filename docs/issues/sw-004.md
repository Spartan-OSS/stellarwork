# SW-004: Test persistent-entry TTL extension and keep_alive boundaries

Status: **Blocked**  
Proposed Drips complexity: **Medium** (organizer/maintainer review required)  
Dependencies: SW-001  
Starting paths: `contracts/escrow/src/test.rs; docs/SPEC.md`

## Problem

Financial records must survive normal use, and dormant storage needs an explicit restoration procedure.

## In scope

- Configure test ledger TTL limits; inspect engagement, milestone, and instance TTLs.
- Advance ledger sequence across thresholds and exercise reads, writes, and keep_alive.
- Verify keep_alive refreshes every milestone of one engagement, not another engagement.
- Document what native tests do and do not simulate about persistent archival/restoration.

## Acceptance criteria

- Tests demonstrate threshold and extension behavior for instance and persistent keys.
- Expired obligations are never recreated as empty or reset liabilities.
- Tests state explicitly that simulated reads alone do not persist network rent extensions.

## Excluded work

No paid keeper service, RPC restoration tooling, or retention-policy invention.
