# SW-007: Build read-only engagement and milestone pages

Status: **Blocked**  
Proposed Drips complexity: **Medium** (organizer/maintainer review required)  
Dependencies: SW-005, SW-006; G4  
Starting paths: `apps/web/ (new); generated bindings from SW-006`

## Problem

Users need a reliable view of agreed scope, milestone states, deadlines, and locked amounts.

## In scope

- Create a small Next.js/TypeScript app using verified read bindings and testnet configuration.
- Display all parties, terms reference, milestones, token identity/decimals, and state badges.
- Handle missing engagement, loading, RPC error, stale data, and archived-entry notices.
- Render evidence references safely; no HTML injection or automatic untrusted resource fetching.

## Acceptance criteria

- Approved, disputed, and expired fixtures render correct state and exact integer-to-decimal amounts.
- Wrong network/config blocks reads with an understandable message.
- Unknown IDs and RPC errors show recoverable states without fabricated zero balances.
- Layout works at 375px and desktop; keyboard access and visible labels covered.

## Excluded work

No transaction actions, backend/indexer, evidence uploading, authentication database, or new contract methods.

## Verification

Commit lockfile; npm test and npm run build pass; attach screenshots and mocked RPC scenarios.

## Handoff and review

Assign one contributor only when every dependency is merged and the baseline is green.
The contributor proposes an approach before changing interfaces, reports blockers, and
links tests/results in the PR. Maintainer reproduces acceptance criteria before merge.
Financial changes require an independent contract review. Draft IDs must be replaced
with actual GitHub issue links after publication. Do not add Wave labels before program
approval. Points are not a promised fixed currency reward.
