# SW-008: Add the client fund and approve transaction flows

Status: **Blocked**  
Proposed Drips complexity: **High** (organizer/maintainer review required)  
Dependencies: SW-006, SW-007  
Starting paths: `apps/web/ transaction adapter and client milestone actions`

## Problem

The read-only interface cannot fund a Pending milestone or approve Submitted work.

## In scope

- Add client-only fund and approve controls according to the state table.
- Simulate, display exact token amount/network/recipient, request signature, submit, and poll confirmed status.
- Separate rejected signature, RPC/contract failure, pending, timeout/unknown result, and confirmed states.
- Refresh state before action and after confirmation; prevent duplicate submissions.

## Acceptance criteria

- Happy paths move verified testnet balances and refresh the milestone page.
- Wrong-role, wrong-network, insufficient-balance, stale-state, rejected-signature, and confirmation-timeout cases have tests.
- Unknown confirmation does not appear as success or trigger blind resubmission.
- Keys remain in wallet; no client approval by freelancer and no action on Disputed work.

## Excluded work

No worker submission UI, arbitrator settlement UI, production tokens, fees, or SDK policy changes.

## Verification

npm test; npm run build; documented testnet fund/approve receipt and balances.

## Handoff and review

Assign one contributor only when every dependency is merged and the baseline is green.
The contributor proposes an approach before changing interfaces, reports blockers, and
links tests/results in the PR. Maintainer reproduces acceptance criteria before merge.
Financial changes require an independent contract review. Draft IDs must be replaced
with actual GitHub issue links after publication. Do not add Wave labels before program
