# SW-009: Implement worker submission and party dispute controls

Status: **Blocked**  
Proposed Drips complexity: **Medium** (organizer/maintainer review required)  
Dependencies: SW-007, SW-008  
Starting paths: `apps/web/ worker/party milestone actions`

## Problem

Workers need to anchor an existing evidence reference, and either party needs a way to dispute Submitted work.

## In scope

- Reuse the verified transaction adapter; add worker-only submit and party-only dispute controls.
- Enforce 1–512 UTF-8 bytes and deadline hints without treating browser time as authoritative.
- Explain that evidence URI is public and documents should remain private.
- Show Disputed state after confirmation and suppress client approval controls.

## Acceptance criteria

- Worker submits a valid URI, then either party can dispute exactly once.
- Outsider, late submit, malformed/oversize input, canceled signing, and stale-state cases have tests.
- No file content or access token is written on-chain or to logs.
- Existing client transaction tests remain green.

## Excluded work

No file-hosting service, AI work grading, dispute outcome selection, or notification provider.

## Verification

npm test; npm run build; testnet submit/dispute evidence.

## Handoff and review

Assign one contributor only when every dependency is merged and the baseline is green.
The contributor proposes an approach before changing interfaces, reports blockers, and
links tests/results in the PR. Maintainer reproduces acceptance criteria before merge.
Financial changes require an independent contract review. Draft IDs must be replaced
with actual GitHub issue links after publication. Do not add Wave labels before program
