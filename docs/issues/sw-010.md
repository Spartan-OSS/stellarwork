# SW-010: Add arbitrator split settlement with exact amount validation

Status: **Blocked**  
Proposed Drips complexity: **High** (organizer/maintainer review required)  
Dependencies: SW-003, SW-007, SW-008  
Starting paths: `apps/web/ arbitrator settlement form and tests`

## Problem

The fixed arbitrator needs to settle a dispute without rounding errors or transferring too much.

## In scope

- Add arbitrator-only settlement controls for Disputed milestones.
- Parse refund in exact base units; derive payout = amount - refund; preview both destinations.
- Use bigint/string handling throughout; reject negative, excessive, or too-precise inputs.
- Reuse confirmed-transaction flow and show Resolved state plus resulting balances.

## Acceptance criteria

- Full refund, full payout, and fractional 70/30 cases settle correctly at configured decimals.
- Exact-sum validation survives values above Number.MAX_SAFE_INTEGER without precision loss.
- Wrong-role and already-resolved attempts fail and do not duplicate transfers.
- Form labels explain that arbitral decisions are final in this MVP.

## Excluded work

No fee pool, appeals, arbitration selection, rate conversion, or percentages stored as floats.

## Verification

npm test; npm run build; documented testnet split receipt and before/after balances.
